Arrow style trial

One set of arrow rules for all 100 pictures with arrows, tried on three of them. “Now” is the live picture; “Trial” is redrawn to the rules. Nothing on the site has changed.

The rules

Main path

The one route the picture is about. Family colour only: the same thickness and the same head as every other arrow. One per picture.

Step

“Leads to.” Ink, 2.5 thick. Most arrows.

Maybe or later

Dashed. Only for something optional, uncertain or still to happen.

Related

A line with a dot at each end. Linked, but nothing flows.

Blocked

A cross instead of a head: stopped, refused or not allowed. Good for guardrails and safeguarding.

Loop

A cycle. Every arc in a loop uses the same curve.

Both ways

Heads at both ends. Rare: only for a real two-way exchange.

  • Every arrow stops 8 short of the shape it points to, so heads never touch or overlap a box.
  • One arrowhead, one thickness: every arrow is 2.5 thick with the same head; only the colour changes.
  • Leave and enter straight on: an arrow leaves a box at right angles to its edge and arrives the same way.
  • Checked on every build: build.py warns if an arrow crosses a box, shape or label it isn’t joined to, if two arrows cross, or if one is too short to read.
  • Near-misses snap straight: two boxes within 6 of lining up get a straight arrow, not a tiny wobble.
  • Calculated, not guessed: each trial arrow is written only as “from this box’s side to that box’s side”. build.py works out the rest: where on the edge it sits, whether it can be straight, and the curve, with both control points straight out from their edge.
  • Read left to right or top to bottom. Labels sit beside an arrow, never on the line.
